# Свой путь — 12 шагов

Русскоязычное приложение с двенадцатью самостоятельными модулями. Работает на телефоне и компьютере без регистрации. Личные записи сохраняются в браузере; сервера заметок и аналитики нет.

## Быстрый запуск

Для запуска на Linux достаточно Python 3. Устанавливать `npm` не нужно.

~~~sh
git clone --branch main --single-branch https://github.com/Nodensss/12SHAGOV.git
cd 12SHAGOV
python3 -m http.server 4173 --bind 127.0.0.1 --directory public
~~~

Откройте [http://localhost:4173](http://localhost:4173). Сервер слушает только это устройство. Остановить: Ctrl+C. Если порт занят, замените `4173` на `4174` в команде и адресе.

У репозитория сейчас другая ветка по умолчанию — Android-проект. Для этого веб-приложения на Linux нужна именно ветка `main`.

Если у вас есть Node.js 22 или новее и `npm` находится в `PATH`, можно запустить встроенный сервер:

~~~sh
npm start
~~~

Раздавайте веб-сервером только public/ или dist/. Исходные документы находятся отдельно от веб-версии в docs/.

## Что работает

| Шаг | Упражнение |
| --- | --- |
| 1 | Карточки «до / во время / после» и повторяющиеся последствия |
| 2 | Компас доступных опор |
| 3 | Распределение действий по зонам ответственности |
| 4 | Инвентаризация с отдельным черновиком по каждой теме |
| 5 | Приватная репетиция разговора и личных границ |
| 6 | Петля привычки: ситуация, реакция, польза и последствия |
| 7 | Просьба своими словами или тихая практика |
| 8 | Список с псевдонимами и вопросами до любых действий |
| 9 | Прямой, косвенный и отложенный вариант исправления |
| 10 | Чек-ин и календарь личных записей без серий и баллов |
| 11 | Выбор практики и мягкий таймер от одной минуты |
| 12 | Ситуации поддержки с уважением к согласию |

В каждом модуле есть введение, вымышленная ситуация, вопросы с пропуском, автосохранение, пауза, закладка и заметка для будущего разговора. Доступны поиск по библиотеке и заметкам, три исходных авторских конспекта, экспорт и импорт JSON, удаление личных данных, крупный шрифт и высокий контраст.

Авторские конспекты открываются отдельной страницей с оглавлением, списками и таблицами. На компьютере кнопку «На весь экран» можно использовать для чтения; если браузер ограничивает этот режим, нажмите F11.

Офлайн-режим готов после первого успешного открытия: файлы приложения и поисковые данные сохраняются Service Worker. Он работает на localhost и HTTPS. Установка на домашний экран зависит от браузера. Индикатор готовности расположен в боковой панели.

Аудио — синтез введения локальным русским голосом устройства: пауза, продолжение, остановка и скорость. При отсутствии локального голоса остаётся текст. Микрофон не используется. Записанного аудио и голосовых заметок в этой версии нет.

Напоминание — добровольно скачиваемое событие .ics с нейтральным названием «Время для себя». Его нужно добавить в свой календарь; там же его можно отключить. Приложение не запускает фоновые уведомления.

## Сюжетная игра «Истории одного двора»

Игра открывается с главной страницы приложения или по адресу [http://localhost:4173/game/](http://localhost:4173/game/). Она рассчитана на вертикальный экран телефона: игрок читает сцену, нажимает «Дальше», делает выбор и в конце может записать мысль в дневник или нажать «Ответить позже». Таймера, очков и оценки ответов нет.

Перед первой главой игрок выбирает героя на экране с каруселью портретов. Сейчас открыт один герой — Наркоман; Алкоголик, Лудоман, Геймер, Скроллер, Курильщик, Шопоголик и Незнакомец видны, но закрыты (`"locked": true` в `vocab.json`). Графика этапов 1–3: все восемь героев и четыре противника используют оригинальные рисованные WebP в `public/game/art/`. У Лудомана, Скроллера и Шопоголика — женские фигуры; эти герои остаются закрытыми. Принятые пять картинок этапа 1 сохранены без изменений. Портреты героев — 640 × 960 (2:3), противников — 640 × 640 (1:1); каждый файл меньше 150 КБ. У Тяги сохранено лицо героя.

Экран выбора героя и бой получили более крупные портреты, тёмные неровные рамки, зерно и градиенты. Шкалы и кнопки оформлены в том же духе; расположение доступно на коротком экране, а `prefers-reduced-motion` отключает необязательное движение. Закрытый герой виден, но его кнопка выбора недоступна. Небольшие исходные SVG `ui-frame.svg` и `ui-grain.svg` задают фактуру, без новых библиотек.

`node scripts/game_art.mjs public/game/art` создаёт только прежние SVG и не воспроизводит WebP. Все старые SVG сохранены. Эталоны и полноразмерные исходники генерации не входят в репозиторий; исходники сохранены отдельно от игры в `generated_images`. Слепые сравнения и оценки двух судей передаются владельцу вместе со скриншотами телефона; решение о смысле образов остаётся за владельцем.

Четвёртый шаг проверяет `python3 tests/game-step04-flow.py`: последовательность слоёв, закрытие боя, усиление приёмов, закладки финала, сохранение прогресса и размеры телефона. Проверка включена в CI.

Для проверки интерфейса запусти `npm run dev`, затем `python3 tests/game-art-flow.py` (нужен Python-пакет `playwright`; браузер можно указать через `CHROMIUM_PATH`). При каждом пуше эту проверку, проход третьего шага и проверку звука (`tests/game-sound-flow.py`: события, фоны по сценам, измеренная громкость каждого звука) запускает CI. Проверяются закрытые герои, размеры кнопок, четыре размера экрана, применение приёмов и загрузка графики без сети.

Короткие экраны: на 390×664 и 320×568 шесть приёмов босса и обе шкалы помещаются без прокрутки страницы. Картинка противника не сжимается меньше 150 px и 96 px соответственно: место ей уступает журнал боя, который прокручивается внутри себя и после каждого хода показывает ответ тяги. Кнопки сохраняют минимум 61 px. На выборе героя описание и точки располагаются выше нижней панели. Незнакомец показан со спины без различимого лица.

Этап 4: у шести приёмов и девятнадцати находок есть оригинальные прозрачные WebP-иконки. Поле `icon` задаёт путь в `skills.json` / `items.json`. Неизвестная находка отображается тёмным силуэтом без раскрытия названия. Иконки не заменяют текст; механизм боя и идентификаторы остаются прежними. Проверки включают отсутствие прокрутки страницы и журнала, границы и перекрытия кнопок, прозрачность и размер файлов, офлайн-список и общий лимит всей графики.

Этап 5: пять оригинальных фонов сцен — двор со скамейкой, кухня, крыльцо с лампой, комната группы и набережная. В JSON главы можно задать необязательное поле `background` с локальным путём `art/scene-yard.webp`; одноимённое поле сцены заменяет фон главы. Если фон не задан, оформление остаётся прежним. Изображения подключены к историям первого и второго шагов и доступны офлайн; текст располагается на тёмной подложке. Экран боя и логика звука не меняются. `python3 tests/game-background-flow.py` проверяет наследование и отключение фона, прежний вид без поля, контраст текста, кнопки на двух высотах и загрузку всех пяти изображений офлайн.

Этап 6: второй шаг открывается живописной картой двора. Пять подписанных мест сохраняют тот же порядок свободного выбора и те же опоры; после трёх опор доступен прежний финал. Переключатель «Карта / Плитки» возвращает запасной вид, выбор запоминается на устройстве отдельно от игрового прогресса. Если изображение или данные карты недоступны, остаются плитки. Кнопки мест доступны с клавиатуры.

Фоны третьего и четвёртого шагов: утренняя кухня с телефоном, лестница перед запертой дверью, остановка под дождём и ночная кухня с тетрадью под лампой. Они подключаются тем же необязательным `background`; сцены без фона сохраняют прежний вид. Боевые иконки увеличены и осветлены, правила размеров кнопок и противника сохранены. `python3 tests/game-map-flow.py` проверяет карту, плитки и аварийный переход к ним, открытие финала, старые записи, офлайн-графику и боевые иконки на 390×664 и 320×568.

Меню разбито на шаги (`steps` в `episodes.json`), и у каждого шага свои правила.

**Шаг первый, «Признание»** — линейный путь: четыре эпизода («Только один раз», «Заначка», «Сестра», «Дверь»), после каждого — пошаговый бой с тягой, от лёгкой («Шёпот») до босса («Тяга»), в конце — испытание «Капкан иллюзий», где нужно отличить ловушки от правды. Победа в бою повышает уровень героя (с 1 до 5). Баланс задуман так, что одной «Силой воли» выиграть нельзя, а броню босса снимает только признание «Я не справляюсь сам»; это проверяют тесты. Проигрыш ничего не отнимает.

**Шаг второй, «Надежда»** открывается после испытания и устроен иначе: боёв нет, вместо списка — карта из пяти мест, куда можно идти в любом порядке. Каждое место даёт опору. Когда опор три, открывается финал «Ночь без драки», и его текст зависит от того, какие именно опоры собраны.

**Шаг третий, «Решение»** открывается после «Ночи без драки». Пять ситуаций — сообщение Лене,
обещание на работе, ключ от помещения группы, отменённая встреча с Тимкой и дорога под дождём —
проходятся с механикой **«Руль»**. Части ситуации можно отнести к своему поступку, просьбе о помощи
или тому, что нельзя контролировать. Каждая раскладка даёт свой отклик и меняет дальнейшие реплики;
оценок и единственного верного решения нет. Затем герой выбирает одно из двух действий.
После каждой ситуации можно ответить на три вопроса или отложить запись. Общий финал помнит
решения шага, разговор с Леной, дверь группы и опоры второго шага. Следующим в меню указан четвёртый шаг.

Раскладка сохраняется после каждого нажатия. Перезагрузка возвращает в незавершённую сцену,
включая выбранный вопрос и его черновик. Новые решения используют прежнее поле `choices`:
старые сохранения, находки и записи остаются доступными. Прямой вход в `/game/` тоже подключает
офлайн-кэш. Сцены третьего шага — авторский черновик для проверки владельцем.

**Рюкзак** хранит находки из сцен (`items.json`). Часть находок зависит от решений, поэтому за одно прохождение собрать все нельзя.

**Звук** по умолчанию выключен: его включает сам игрок кнопкой в шапке любого экрана или в меню, выбор запоминается на устройстве. Все звуки синтезируются в браузере (`sound.js`), аудиофайлов нет. Есть короткие звуки событий (смена сцены, выбор, запись в дневник, приёмы и удары в бою, победа, срыв) и тихие фоны мест: двор, кухня, комната группы, набережная, дождь, ночь, бой. После победы над боссом остаётся тишина. Какой фон звучит в какой сцене и общая громкость заданы в `data/sounds.json`. Послушать все звуки по кнопке можно на странице `/game/sounds.html`.

**Шаг четвёртый, «Тетрадь»** открывается после «На завтра». Это пять страниц — обиды, страхи, поступки, люди и «Что во мне есть» — по три последовательных слоя на каждой. Страницы можно выбирать в любом порядке; следующий слой открывается после предыдущего. Бой со Стыдом доступен после первого слоя всех пяти страниц. Пройденные слои усиливают соответствующие приёмы, а финал «Тетрадь на столе» учитывает пройденные страницы и оставленные закладки. Тексты и механика сохранены из авторского черновика. Четвёртый шаг принят владельцем. Для Стыда подготовлен собственный WebP-портрет; у шести находок и пяти приёмов страницы — отдельные прозрачные иконки. Прежний SVG сохранён.

**Шаг пятый, «Разговор»** открывается после «Тетради на столе». Сначала — суббота у Марата и договорённость о паузах. Затем пять страниц читаются в любом порядке; закладки четвёртого шага предлагаются первыми. На каждой есть три выбора: прочитать как есть, смягчить или оставить на другой день. Смягчённое можно перечитать. Чтение зависит от глубины исходной страницы, а шкала «Тайна» считает страницы, ещё не прозвучавшие как есть. Отложить все пять и закончить разговор — допустимый путь. Финал помнит актуальные решения и ведёт к шестому шагу. Вопросы дневника необязательны. Боя нет; используются готовые кухня и ночь, без новой графики и звуков. Пятый шаг принят владельцем.

`python3 tests/game-step05-flow.py` проверяет три решения каждой страницы, глубину 1–3, закладки и свободный порядок, перечитывание, все отложенные страницы, финал, выбор и два черновика после перезагрузки, офлайн и прежние v1 записи. Тест включён в CI.

**Шаг шестой, «Готовность»** открывается после «После чая». Неделя обычной трезвой жизни: четыре петли — соврать, ударить первым, взять всё под контроль, уйти первым. Они проходятся в любом порядке. Сначала привычка срабатывает сама, затем игрок собирает карту из четырёх клеток: что запустило, что сделано, настоящая польза и цена. У каждой клетки два верных аспекта события; проверки на «правильность» нет. После отметки «готов попробовать иначе», «хочу понаблюдать» или «пока держусь за это» происходит новый случай с тем же триггером. Попробовать иначе можно со своей ценой; старый способ остаётся возможным. Все три отметки позволяют закончить шаг. Пройденный узел ослабевает, но не исчезает; процентов готовности нет. Тексты помнят глубину тетради и чтение Марату. После четырёх петель — финал с мостом к седьмому шагу.

`python3 tests/game-step06-flow.py` проверяет четыре петли со всеми отметками, оба действия после «попробовать», карту и её изменение, связь с шагами 4–5, финал, старые v1 записи, перезагрузку посреди петли и офлайн на 390×664 и 320×568. Проверка включена в CI.

**Незаконченный бой** сохраняется: после перезагрузки страницы игрок возвращается на тот же ход. Выход в меню и конец боя его стирают.

Решения запоминаются: реплика или переход с полем `if` / `ifNot` показывается только тем, кто выбрал вариант, прошёл эпизод или выиграл бой с указанным `id`. Все эпизоды, кроме самого первого, написаны под героя-наркомана; чтобы открыть другого героя, их текст нужно будет адаптировать.

Весь текст игры лежит в `public/game/data/`, код компонентов править не нужно:

| Что добавить | Где |
| --- | --- |
| Вопрос для дневника | В файле главы `chapters/*.json`: объект `{ "id", "text" }` в массив `questions` и его `id` в `questionIds` нужной сцены типа `journal` |
| Реплику или сцену | В файле главы: `scenes` → `lines`; переход задаёт `next` (id сцены или список маршрутов `[{ "if", "to" }, { "to" }]`) или `choice.options[].next` |
| Главу | Новый файл в `chapters/` и строка в `episodes.json`; для офлайн-режима добавьте путь в `ASSETS` в `public/sw.js` |
| Бой | Файл в `fights/` (имя, уровень тяги, картинка, здоровье, атаки, список приёмов, тексты победы и срыва, награда; необязательное поле `victoryTitle` задаёт заголовок победы, без него — «Тяга отступила») и строка с `"type": "fight"` в `episodes.json` |
| Приём | Объект в `skills.json` (урон, цена, лечение, перерыв) и его `id` в поле `skills` нужного боя. Необязательное `page` связывает приём со страницей тетради: урон и лечение умножаются на число пройденных слоёв (1–3), `says` задаёт три реплики по глубине |
| Испытание | Файл в `trials/` (карточки: фраза, `trap` — ловушка или правда, объяснение) и строка с `"type": "trial"` в `episodes.json` |
| Ситуацию с «Рулём» | Сцена `type: "steering"` в файле главы: три `zones` (`act`, `help`, `release`), `parts` с вариантами по зонам, `intro`, `continueLabel` и `next`. У каждого варианта свои постоянный `id` и текст отклика `text` |
| Карту двора | Необязательное `map` у шага в `episodes.json`: `art` — WebP, `alt` — описание, `places` — список `{ id, x, y }` с существующими id мест и координатами в процентах (x: 22–78, y: 10–90, чтобы подписи помещались). Сам финал остаётся отдельной карточкой. Без данных или картинки используются прежние плитки |
| Петли привычки | `layout: "loops"` у шага: `intro`, `finale`, `labels`, `loops` (id, title, chapter, notebookPage, choice, try/watch/hold). `notebookPage` — связь с тетрадью без увеличения её глубины. Финал требует все главы петель через `needs` |
| Карту петли | Сцена `type: "habit-map"`: `intro`, `continueLabel`, `next`, четыре `cells` с постоянными `id`, `title` и `options[{id,text}]`. Любой вариант допустим; выбранные id доступны для условий реплик. Продолжение после выбора в каждой клетке |
| Разговор по страницам | `layout: "conversation"` у шага: `intro`, `finale`, `cover`, `labels` и `pages`. У страницы — `id` исходной страницы тетради, `title`, `chapter`, `bookmark`, `choice`, `read` / `soften` / `later`, `revisitChoice` / `reread` (постоянные id выборов). Не добавляйте верхнее поле `page` элементам разговора: оно считает глубину четвёртого шага |
| Условие чтения | У реплики `depth: { of: [id слоёв], min, max }` считает пройденные слои, `ifAny` / `ifNone` — наличие любого решения из списка. У финала в индексе `allOfAny` требует хотя бы один id в каждой группе; несколько решений одной страницы не заменяют другую |
| Страницу тетради | При `layout: "notebook"` у шага задаются `pages` (`id`, `title`, `skill`, необязательное `note`) и `depths` — подписи трёх слоёв. В элементах `episodes.json`: `page` — id страницы, `depth` — 1, 2 или 3, `after` связывает последовательные слои. Для боя `needs` перечисляет первые слои всех страниц |
| Иконку | Прозрачный WebP в `art/icons/`, путь `icon` у приёма в `skills.json` или находки в `items.json`; файл также добавляется в офлайн-кэш |
| Находку | Объект в `items.json`: название, текст и `when` — `id` решения, эпизода или боя; `"kind": "support"` — опора на карте шага |
| Фон сцены или громкость | В `sounds.json`: `ambience.chapters` — фон эпизода, `ambience.scenes` — фон отдельной сцены, `volume` и `ambienceVolume` — громкость. Новый звук или фон — рецепт в `sound.js` и название на странице `sounds-page.js` |
| Шаг | Объект в `steps` файла `episodes.json`: `layout` — `path` (список), `map` (места), `wheel` (ситуации «Руля»), `notebook` (страницы тетради), `conversation` (разговор по страницам) или `loops` (петли привычки), `after` — условие открытия, `lockedText` — его пояснение |
| Плашку следующего шага | `nextStep` в `episodes.json`: `title` и `teaser` |
| Портрет | Файл WebP в `public/game/art/`: герой 2:3, противник 1:1, до 150 КБ; путь `art` в `vocab.json` или `fights/*.json`. Добавьте файл в `ASSETS` в `public/sw.js` и повысьте номер кэша; весь каталог графики — до 3 МБ |
| Героя | Объект в `variants` файла `vocab.json`: название, эпитет, фраза, описание, картинка `art` (WebP или SVG 2:3) и слова для `{once}`, `{after}`, `{without}` |

Идентификаторы (`id`) глав, сцен, реплик, вариантов выбора и вопросов постоянные: к ним привязаны прогресс и записи игроков. Новым элементам давайте новые `id`, старые не переименовывайте. `npm test` проверяет, что все ссылки между сценами существуют, а каждая ветка доходит до концовки; в браузере ошибки данных выводятся в консоль.

У части ситуации «Руля» три варианта: `{ "id": "уникальное-решение", "zone": "help", "text": "Отклик сцены" }`.
Выбранный `id` доступен для `if` / `ifNot` у следующих реплик и для `when` у находки. Раскладку
можно менять до продолжения; прежний вариант этой части перестаёт считаться выбранным.
Текст, вопросы, предметы и варианты последствий добавляются в JSON, без правки компонентов.

Проверка третьего шага: `npm run check`, `npm test`, `npm run build`.
Браузерный проход: `python3 tests/game-step03-flow.py` (Playwright и Chromium).
Он проверяет обе ветки всех новых глав, сохранение раскладки и двух черновиков, офлайн-проход,
старые записи, экран 390/320 px и разные финалы. Для собранной версии можно задать `GAME_WEB_ROOT=dist`.

Прогресс, выбранный вариант и дневник игры хранятся в localStorage под ключом `12shagov-game-v1`. PIN основного приложения эти записи не шифрует. Они удаляются кнопкой в дневнике игры и вместе с личными данными приложения. В экспорт JSON они пока не входят.

## Приватность

- Без PIN записи находятся только в localStorage текущего профиля браузера.
- При включении PIN вся личная запись шифруется AES-GCM. Ключ получается через PBKDF2 SHA-256: 210 000 итераций, случайная соль. PIN и ключ не записываются на диск.
- При сворачивании защищённое приложение закрывает записи. Потерянный PIN восстановить нельзя.
- Экспорт JSON содержит открытый текст. Храните такую копию самостоятельно.
- Очищение данных браузера удаляет и заметки; для резервирования есть экспорт/импорт.
- Контакты поддержки пользователь добавляет сам; приложение не отправляет сообщения и не публикует заметки.

Это инструмент для размышления и знакомства с материалами. Он не диагностирует и не заменяет встречи, спонсорство, медицинскую или кризисную помощь.

## Источники и редакторский статус

docs/step01.md–step03.md сохранены как авторские рабочие конспекты. Все восемь файлов библиотеки находятся в docs/libNarco/ с исходными именами. Тексты шагов и ТЗ — в docs/materials/.

outputs/Все_12_шагов_полный_текст.txt содержит все двенадцать исходных TXT побайтно, в порядке 1–12, с разделителями между шагами.

Разные редакции не объединены. Цитаты и поиск указывают конкретный источник, издание, страницу PDF и строки извлечённой страницы либо строки TXT.

По умолчанию непроверенные источники закрыты. Для личного чтения можно включить просмотр копий со статусом unverified в настройках. Это не редакторское одобрение. Явно черновые и внутренние материалы исключены из поисковых данных и не открываются этим переключателем. Подробности: [CONTENT_POLICY.md](docs/CONTENT_POLICY.md).

Репозиторий приватный. Публикация приложения в открытый доступ и подтверждение статусов библиотеки — отдельные действия, в этом изменении они не выполнялись.

### Шаг седьмой «Просьба»

После `step06-ask` — встреча с Маратом в полвосьмого, пять встреч в любом порядке (Степаныч, Тамара, Лена, Тимка, сосед) и финал «Свои слова». Марат появляется в начале и конце. У каждого человека свой язык; религиозные, светские, бытовые слова и молчание равноправны. После встречи короткая петля помнит отметку шестого шага: можно попробовать просьбу или пройти мимо. Найденные слова сразу доступны в отдельной копилке.

Новый `layout: "words"`: `intro`, `finale`, `words[{id,text,register,whenAny}]`, `labels`, `formats[{id,text}]`, `feelings[{id,text}]`. Копилка определяется прежними id выборов; отдельный счётчик духовности не создаётся. Финал требует пять завершённых встреч через `needs`. Плашка следующего шага — восьмой.

Новая сцена `type: "own-words"`: `title`, `intro`, `minParts`, `maxParts`, `final`, `next`. В короткой паузе — один–два фрагмента или молчание; в финале — две–четыре части в своём порядке, способ произнести и чувство. Изменение порядка доступно кнопками, перетаскивание не требуется. Полное молчание позволяет закончить без слов. Все личные вопросы можно отложить.

Необязательное поле сохранения `ownWords`: `drafts[sceneId]` (`parts`, `silent`, `format`, `feeling`, `complete`) и `final` — id завершённой финальной сборки. Каждое действие сохраняется. `requestText` восстанавливает фразу из постоянных id; она видна после прохождения и в меню. Старые сохранения без поля открываются прежним способом. Тексты оригинальные, без цитат; фоны и звук взяты из готовых.

`tests/game-step07-flow.py` включён в CI: свободный порядок встреч, оба пути каждой петли, все три отметки шестого шага, перестановка/удаление частей, перезагрузка посреди сборки, три формата, полное молчание, финал, прежние записи и офлайн на 390×664 и 320×568. Данные и чистая логика проверяются в `tests/game.test.mjs`. Новые тексты ждут чтения владельцем.

### Шаг восьмой «Список»

После `step07-own` — вечер во дворе с Маратом («Пока только список»), затем фасад дома из восьми окон в любом порядке: Лена, Тимка, мать, бытовка склада (Колян), соседка тётя Валя, Сиплый, своё отражение и «Своё окно», которое игрок подписывает сам. Финал «Вопросы для Степаныча» открывается после пяти любых окон; его реплики собираются из окон с отметками «пока не готов» и «не знаю». Мост к девятому шагу: «не сегодня и не в одиночку».

Новый `layout: "windows"`: `intro`, `finale`, `windows[{id,title,chapter,choice,ready,notyet,unsure}]`, `labels`. Отметка готовности — обычный выбор главы, нового поля сохранения нет (`windowsState`, `validateWindows` в `engine.js`). Цвет окна показывает только отметку; баллов и процентов нет.

Каждая глава окна: история с отсылками к прошлым шагам (правда Лене, дверь группы, страницы тетради «Люди», «Поступки», «Что во мне есть», петля вранья шестого шага, слова седьмого) → карточка из трёх вопросов: подпись (можно буквой или псевдонимом), что произошло, что нужно понять до действий → одна из трёх равноправных отметок → концовка. Окно Сиплого — про безопасность: «есть двери, которые не открывают». Кнопок «написать человеку» нет; тест проверяет, что выборы не предлагают связаться с людьми.

Все тексты — в `public/game/data/chapters/step08-*.json`. Логика проверяется в `tests/game.test.mjs`. Проверки в браузере (`tests/game-step08-flow.py`) пока нет. Новые тексты ждут чтения владельцем.
