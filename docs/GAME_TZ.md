# ТЗ: продолжение сюжетной игры «Истории одного двора»

Документ для агента-разработчика, который продолжает работу над игрой. Он описывает, что уже сделано, по каким правилам это устроено и что делать дальше. Перед началом прочитайте его целиком, затем `README.md` (раздел про игру) и `docs/CONTENT_POLICY.md`.

## 1. Что это за проект

Игра — часть веб-приложения «Свой путь — 12 шагов» (ветка `main`). Это сюжетная игра для телефона по мотивам программы «12 шагов»: игрок проходит сцены, принимает решения и может записывать мысли в личный дневник. Цель — вовлечь человека в программу, а не заменить её.

Владелец проекта — разработчик без команды. Он хочет сам добавлять главы, вопросы и героев, не трогая код. Поэтому весь текст и все числа лежат в JSON.

Игра открывается по адресу `/game/` и с карточки на главной странице приложения.

## 2. Что уже сделано

**Герой.** Экран выбора героя с каруселью из восьми портретов. Открыт один — Наркоман (`drugs`). Остальные семь видны, но закрыты (`"locked": true` в `vocab.json`). Владелец решил: сначала вся игра делается для Наркомана, остальные герои — позже.

**Шаг первый, «Признание»** — линейный путь из девяти элементов:

| № | Элемент | Тип |
| --- | --- | --- |
| 1 | Только один раз | эпизод |
| 2 | Шёпот | бой |
| 3 | Заначка | эпизод |
| 4 | Заначка | бой |
| 5 | Сестра | эпизод |
| 6 | Старая компания | бой |
| 7 | Дверь | эпизод |
| 8 | Тяга | бой-босс |
| 9 | Капкан иллюзий | испытание |

**Шаг второй, «Надежда»** — открывается после испытания. Боёв нет. Карта из пяти мест (Группа, Скамейка, У Лены, Набережная, Утро), которые проходятся в любом порядке; каждое даёт опору. Три опоры из пяти открывают финал «Ночь без драки», текст которого зависит от собранных опор.

**Шаг третий, «Решение»** — открывается после «Ночи без драки». Механика «Руль» (`layout: "wheel"`): в каждой из пяти ситуаций игрок раскладывает три части по зонам «Мой поступок», «Попросить помощи», «Отпустить итог», затем делает выбор; финал «На завтра» зависит от решений шага. Тексты шага — черновик: они суше первых двух шагов, в них мало диалогов и живых персонажей.

**Сквозные системы:** уровень героя (1–5, растёт за победы в боях), рюкзак с находками, дневник с отложенными вопросами, сохранение прогресса в браузере, офлайн-кэш.

**Постоянные персонажи:** Марат (знакомый, ходит на группу), Лена (сестра), Тимка (племянник, 7 лет), Сиплый (прежняя компания), Тамара (учитель физики, с группы), Степаныч (старик с группы, девять лет чистоты), «Голос в голове».

## 3. Как устроен код

Стек — чистый JavaScript (ES-модули) без сборки и без зависимостей. Не добавляйте React, TypeScript, Vite, npm-пакеты.

| Файл | Назначение |
| --- | --- |
| `public/game/index.html` | Оболочка страницы |
| `public/game/game.js` | Экраны и обработчики; единственный файл, работающий с DOM |
| `public/game/engine.js` | Чистая логика: прогресс, условия, дневник, проверка глав |
| `public/game/battle.js` | Чистая логика пошагового боя |
| `public/game/game.css` | Стили; вертикальный экран телефона, тёмная тема |
| `public/game/data/episodes.json` | Шаги (`steps`) и порядок всех элементов (`chapters`) |
| `public/game/data/chapters/*.json` | Эпизоды: сцены, реплики, выборы, вопросы дневника |
| `public/game/data/fights/*.json` | Бои |
| `public/game/data/skills.json` | Приёмы героя в боях |
| `public/game/data/trials/*.json` | Испытания «ловушка или правда» |
| `public/game/data/items.json` | Находки и опоры |
| `public/game/data/vocab.json` | Герои и слова-подстановки |
| `public/game/art/*.svg` | Портреты героев и противников |
| `scripts/game_art.mjs` | Генератор портретов: `node scripts/game_art.mjs public/game/art` |
| `tests/game.test.mjs` | Тесты данных и логики |
| `public/sw.js` | Офлайн-кэш; список `ASSETS` ведётся вручную |

### Ключевые правила данных

- **Идентификаторы постоянны.** `id` глав, сцен, реплик, вариантов выбора, вопросов, боёв и находок нельзя переименовывать: к ним привязаны прогресс и записи игроков. Новому — новый `id`.
- **Условия.** Поля `if` и `ifNot` у реплики или маршрута `next` ссылаются на `id` выбранного варианта, пройденного эпизода, испытания или выигранного боя — из любой части игры. Набор «сделанного» собирает `picked(game)` в `engine.js`.
- **Открытие элементов.** `after` — что нужно пройти раньше. `needs: { count, of }` — пройти хотя бы `count` элементов из списка.
- **Шаги.** `layout: "path"` — список по порядку, `layout: "map"` — плитки мест. `after` у шага — условие его открытия.
- **Подстановки.** `{once}`, `{after}`, `{without}` используются только в самом первом эпизоде. Остальные эпизоды написаны прямо под Наркомана.
- **Хранение.** Всё состояние игры лежит в `localStorage` под ключом `12shagov-game-v1`; форму задают `freshGame()` и `normalizeGame()`. При добавлении поля обновляйте обе функции так, чтобы старые сохранения открывались.

### Запуск и проверки

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory public
npm run check
npm test
npm run build
```

Игра: `http://localhost:4173/game/`. Node.js 22 или новее. Все три команды должны проходить перед каждым коммитом; CI запускает их же.

## 4. Правила содержания

Эти правила важнее любых идей по механике.

1. **Не цитировать литературу.** Тексты АН защищены авторским правом, а источники в проекте помечены как непроверенные или черновые. Сюжет и диалоги — только оригинальные. Темы берите из авторских конспектов `docs/step01.md`–`step03.md` и записывайте в поле `basedOn` главы, из каких разделов взята идея.
2. **Без оценки игрока.** Нет таймеров, очков за личные ответы, «правильных» и «неправильных» веток. Обе ветки любого выбора приводят к осмысленному итогу. Проигрыш в бою называется «Срыв», ничего не отнимает и подсказывает, что попробовать иначе.
3. **Не требовать доказывать тяжесть.** Никаких сравнений «у кого хуже», никаких шкал зависимости.
4. **Дневник необязателен.** У каждой страницы дневника есть «Ответить позже». Вопросы дневника формулируются без грамматического рода («Что я повторяю…», а не «Что я делал…»): их читает игрок о себе.
5. **Герой — мужчина.** В репликах о герое допустим мужской род («дядя», «сам положил»).
6. **Никаких инструкций по употреблению.** Вещества не называются, способы, дозы и добыча не описываются. В тексте — «коробок», «вещества», «тема на вечер».
7. **Программа не религиозная.** «Сила» — любое своё понимание; никто из персонажей не проповедует и не говорит герою, кто он и что ему делать. Персонажи говорят о своём опыте.
8. **Зависимость — не внешний враг, а болезнь внутри.** Противники в боях — формы тяги и самообмана, а не вещества и не демоны.
9. **Смысл механики совпадает со смыслом шага.** В первом шаге «Сила воли» всегда проигрывает, а босса открывает только признание бессилия — это проверяется тестами. Не ломайте это балансом.
10. **Это не лечение.** Сноска о живой поддержке в меню остаётся.

Тон: короткие реплики, настоящее время, второе лицо («ты выходишь во двор»), бытовые детали вместо лозунгов, без морали в конце сцены.

## 5. Что делать дальше

### Задача 1. Шаг третий, «Решение» — выполнена

Описание оставлено как образец постановки задачи на шаг.

Напишите и соберите третий шаг целиком для героя-наркомана.

- **Источники:** `docs/step03.md` (основной), `docs/materials/ТЗ_Модуль_Шаг_03_Третий.md`, описание шага 3 в `public/steps.js` (упражнение «что в моей власти?» с тремя зонами).
- **Завязка:** второй шаг кончается вопросом героя: «если Сила есть и она не против меня — готов ли я ей довериться?». Третий шаг начинается отсюда.
- **Своя механика.** Каждый шаг играется иначе: первый — линейный путь с боями, второй — карта и сбор опор. Третьему нужна третья механика. Предложение: «Руль». Герой попадает в ситуации, где что-то идёт не по плану, и раскладывает части ситуации по зонам «в моей власти — мой поступок», «могу попросить помощи», «не в моей власти — отпустить». От раскладки зависит, как разворачивается сцена. Можно предложить другую механику, если она точнее передаёт «принять решение и отпустить контроль над результатом»; согласуйте её с владельцем до реализации.
- **Объём:** 4–6 сцен по 2–4 минуты и финал, который зависит от решений шага. В каждой сцене — выбор из двух действий и страница дневника с 2–3 вопросами.
- **Связь с прошлым:** используйте `if` / `ifNot` на решения первых двух шагов (сказал ли герой правду Лене, вошёл ли в дверь, какие опоры собрал). Минимум три таких отсылки.
- **Находки:** добавьте предметы шага в `items.json`.
- **Открытие:** шаг открывается после `step02-night`. Плашку «Шаг третий · В работе» в меню замените на следующий шаг.

### Задача 2. Шаги 4–12

После приёмки третьего шага — по одному шагу за раз, каждый со своей механикой. Авторских конспектов для шагов 4–12 нет: есть только подборки в `docs/materials/Шаг_NN_*.txt` (дословные фрагменты, цитировать нельзя) и ТЗ модулей `docs/materials/ТЗ_Модуль_Шаг_NN_*.md` — в них описаны цель и вовлекающий элемент каждого шага, от них и отталкивайтесь. Перед каждым шагом коротко предложите владельцу механику и дождитесь ответа.

### Задача 4. Графика (следующая)

Сейчас графика — самое слабое место игры: портреты героев и противников нарисованы кодом (плоский SVG из `scripts/game_art.mjs`), у сцен нет фонов. Задача — поднять визуальное качество, не меняя сюжет, механики и `id`.

**Метод.** Используйте цикл из навыка `dream-loop` (https://github.com/achimala/dream-loop, лицензия MIT; установка: `npx skills add achimala/dream-loop`):

1. сгенерировать картинку-эталон — как экран должен выглядеть;
2. собрать экран, ориентируясь на эталон;
3. отдельный агент-критик сравнивает живой скриншот телефона (390 px) с эталоном и пишет замечания;
4. дорабатывать, пока критик не примет.

Из навыка берётся только этот цикл. Игра остаётся двумерной: не добавляйте Three.js, 3D-сцены, Blender и любые библиотеки.

**Порядок работ.** После каждого этапа — остановка и показ владельцу; следующий этап только после его «да».

| Этап | Что сделать |
| --- | --- |
| 1. Проба | Портрет Наркомана и четыре противника первого шага (Шёпот, Заначка, Старая компания, Тяга). Показать владельцу «было / стало» |
| 2. Герои | Остальные семь портретов в том же стиле (герои остаются закрытыми) |
| 3. Экраны | Экран выбора героя и экран боя: рамки, свет, подача класса, удары и шкалы |
| 4. Фоны | Двор со скамейкой, кухня, крыльцо с лампой над дверью, комната группы, набережная. Фон не должен мешать читать текст |
| 5. Карта | Карта двора для второго шага вместо плиток |

**Стиль.** Единый для всей игры: мрачный, рисованный, с цветной подсветкой — у каждого героя и противника свой цвет (сейчас: Наркоман — зелёный, Шёпот — бледно-зелёный, Заначка — янтарный, Старая компания — красный, Тяга — фиолетовый). Палитра интерфейса задана переменными в начале `public/game/game.css`; не ломайте её.

**Рамки содержания для картинок** (в дополнение к разделу 4):

- Не изображать употребление, шприцы, вещества, упаковки и атрибутику. Допустимы намёки, уже принятые в тексте: спичечный коробок, телефон с сообщением, дым.
- Герой показан запущенным, но человеком: без издёвки, карикатуры, смакования увечий и «зомби».
- Противники — формы тяги и самообмана, а не демоны и не вещества. У босса «Тяга» — лицо самого героя.
- Не изображать реальных людей, чужих персонажей, логотипы, бренды и узнаваемые стили конкретных игр. Только оригинальная графика.
- Дети (Тимка) — только нейтрально и в безопасном контексте; лучше показывать его рисунок, а не его самого.
- Никаких религиозных символов в сценах про «Силу».

**Технические требования.**

- Картинки лежат в `public/game/art/`. Пути задаются в данных (`art` в `vocab.json` и файлах боёв); для фонов добавьте необязательное поле в сцену или главу, чтобы владелец мог менять фон без правки кода. Сцена без фона должна выглядеть как сейчас.
- Формат — WebP (или SVG, если рисуется кодом). Портрет героя 2:3, противник 1:1. Каждый файл до 150 КБ, вся графика игры — до 3 МБ.
- Все новые файлы — в `ASSETS` в `public/sw.js`, номер кэша повысить. Игра должна по-прежнему открываться офлайн.
- Старые SVG не удалять, пока владелец не принял замену. Если портреты больше не рисуются скриптом, отметьте это в `README.md`.
- Сгенерированные эталоны в репозиторий не коммитить.
- Текст на всех экранах остаётся читаемым: контраст не ниже 4,5:1, работает `prefers-reduced-motion`.

**Приёмка.** Действуют критерии раздела 6, а также: тест проверяет, что каждый файл из данных существует и укладывается в лимит размера; владельцу показаны скриншоты телефона «было / стало» по каждому этапу.

## 6. Критерии приёмки для каждого нового шага

- Шаг проходится от начала до конца на экране телефона шириной 390 px без горизонтальной прокрутки; кнопки не ниже 44 px.
- Обе ветки каждого выбора ведут к концовке и отличаются по тексту.
- «Ответить позже» работает; черновик дневника и место в сцене восстанавливаются после перезагрузки.
- Старые сохранения открываются; прогресс первых шагов не теряется.
- Весь новый текст и числа — в JSON; для добавления вопроса или сцены код править не нужно.
- У каждой главы заполнены `basedOn` и `disclaimer`; дословных цитат литературы нет.
- В `tests/game.test.mjs` добавлены тесты на новые данные и новую логику. `validateChapter` проходит для всех глав; все условия `if` / `ifNot` / `when` ссылаются на существующие `id`.
- `npm run check`, `npm test`, `npm run build` проходят.
- Новые файлы добавлены в `ASSETS` в `public/sw.js`.
- В `README.md` обновлены описание игры и таблица «что где добавить».
- Игра проверена в настоящем браузере (в окружении есть Playwright с Chromium), а не только тестами.

## 7. Как работать

- Ветка разработки — `main`. Pull request не создавать, пока владелец не попросит.
- Один шаг — один коммит или несколько небольших; сообщение коммита на английском, по делу.
- Не менять основное приложение (`public/app.js`, `public/storage.js` и остальное вне `public/game/`), кроме списка офлайн-файлов и проверок в `package.json`.
- Не трогать исходные материалы в `docs/libNarco/`, `docs/materials/`, `outputs/`.
- Владелец пишет коротко и по-русски, отвечать ему тоже по-русски, без жаргона разработки. В конце каждой работы сообщать: что сделано, как открыть, что проверено и что осталось.
- Тексты сцен — черновик, пока владелец их не прочитал: он знает программу и людей лучше. Прямо просите его проверить деликатные сцены.
